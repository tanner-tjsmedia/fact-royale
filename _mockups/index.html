These are drafts, not production code. Everything shared lives in mock.css; each page adds only what is specific to it. That is the test, not tidiness: if a design needs a dozen per-page overrides the system is wrong, and across thirteen screens it needed almost none. The two concepts at the end exist to check the same thing from the other direction — board mode introduced exactly one new component, and the live event none at all.

If the direction is approved, the real token set and the shared components get extracted from these files into tokens.css, which also ends the duplication between tokens.css and style.css that the migration note in tokens.css admits to and never finished.

_mockups/ is underscore-prefixed so Jekyll never publishes it, the same reason _app/ is named that way. Nothing here reaches the live site.
